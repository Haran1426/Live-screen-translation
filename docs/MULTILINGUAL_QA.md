# 다국어 OCR·번역 fixture

## 범위

`MultilingualPipelineTest`는 직접 작성한 문장을 메모리 Bitmap에 그려 영어·일본어·중국어·한국어 OCR과 서로 다른 12개 언어 방향을 검사한다. 실제 앱/외부 앱의 화면, 저장된 스크린샷, 사용자 문서를 입력하지 않는다. Bitmap과 인식/번역 결과, 로그 검사 버퍼는 파일로 저장하지 않는다.

| 원문 언어 | 직접 작성한 예문 |
| --- | --- |
| 영어 | The library opens at 9 in the morning. |
| 일본어 | 図書館は午前9時に開きます。 |
| 중국어 | 图书馆上午9点开放。 |
| 한국어 | 도서관은 오전 9시에 문을 엽니다. |

각 언어의 OCR 결과와 다른 세 언어로 번역한 결과에서 해당 언어의 ‘도서관’과 ‘9시’에 대응하는 기본 키워드를 확인한다. 번역 결과가 원문과 동일한지도 검사하고, 원문/인식문/번역문 전체와 알려진 SDK payload 진단이 해당 프로세스 Logcat에 없는지 확인한다. 예외 메시지와 실제 결과 텍스트를 JUnit 실패 출력에 넣지 않는다.

고정된 개발용 경고를 한 번 발생시키고, 로그 보호가 이를 고정된 안전 문구로 바꿔 남겼는지도 확인한다. 로그 읽기가 실패해 빈 버퍼만 얻은 경우를 성공으로 간주하지 않는다.

## 0.1.3 실제 release 연습 화면

선택한 원문 언어가 연습 화면의 제목/본문/복사에 반영된다. API36 x86_64의 최종 R8 release(`debuggable=false`, versionCode 4004)에서 en→ko, ja→ko, zh→ko, ko→en을 각각 검사해 모두 통과했다. 실제 Android 동의/원문 제목/네이티브 오버레이 키워드/멈춤 시 제거·재개/원문과 결과 로그 부재를 확인했다. 원래 언어 설정은 각 검사 finally에서 복원했다. 나머지 8개 실제 화면 방향과 자연스러움은 미검증이다.

첫 일본어 검사는 이동 버튼이 큰 제목 첫 부분을 가려 실패했다. 겹치는 OCR 문단을 제외하는 설계를 유지하며 CJK 화면의 그림을 제목 앞에 배치했다. 수정 후 핵심 원문이 버튼 아래에 놓여 세 언어 모두 실제 캡처 경로를 통과했다. 보안 창/로그 보호/R8 규칙을 완화하지 않았다.

직접 작성한 연습 화면만 QA 이미지로 보관했다. 검은 영역은 `FLAG_SECURE`인 이동 버튼/번역 카드이며, 실제 번역문이 보이는 이미지로 제시하지 않는다. 텍스트 결과는 실제 native TextView에서 자동 검사했다.

이미지는 로컬 `docs/qa/0.1.3/`에만 보관하며 GitHub 소스/릴리스에는 포함하지 않는다. 기록 파일은 `practice-ja-initial.png`, `practice-ja.png`, `practice-zh.png`, `practice-ko.png`다.

이미지에서 글꼴/줄바꿈과 제목이 기본 버튼에 가려지지 않는 배치를 확인했다. 사용자 이동/큰 글꼴/다른 화면 비율의 모든 겹침을 보장하는 결과는 아니다. 카드가 가린 원문은 카드를 접고, 버튼이 가린 문단은 버튼을 옮겨 읽는다. 실제 release 재현 명령은 [QA 절차](QA.md)를 따른다.

## 0.1.5 긴 문단·혼합 언어

0.1.5+6은 12문단/문단당 600 코드포인트를 넘어 제외·축약한 경우 카드/홈 상태에 일부만 번역했다는 고정 안내를 표시한다. 같은 번역 앞부분을 재사용해도 제한 여부는 갱신한다. UTF-16 surrogate pair를 중간에 자르지 않으며 문장/복합 grapheme 경계까지 보장하는 것은 아니다. 단위 7개와 네 언어 연습 화면의 320dp/1.4배 글꼴·복사·전환 테스트가 통과했다.

API36 x86_64의 실제 R8 release에서 `reading-limits` 1개가 통과했다. 기본 영어 예문 번역 후 긴 문단으로 전환해 혼합 행과 native 일부 번역 안내/한국어 결과를 확인하고 멈춤 시 제거·재개 시 복원·기본 예문 복귀 후 안내 해제를 확인했다. 새 공유 동의, 로그 양성 대조, 원문 앵커/번역 본문 로그 부재 및 설정 복원도 포함한다. CJK 긴 문단의 실제 release 검사를 대신하는 결과는 아니다.

`MixedReadingTest`의 작성된 한 Bitmap에는 en/ja/ko/zh 네 문장과 각 행의 A17 식별자가 있다. 네 OCR 선택에서 자기 언어의 도서관 단어와 ASCII 식별자를 확인하고 로그 양성 대조/원문·OCR 결과 로그 부재를 검사했다. API36에서 `OK (4 tests)`다. 아래는 정해진 단어 앵커가 관찰됐는지만 기록한 것이며 문장 전체 인식률이나 번역 정확도가 아니다.

## 0.1.6 후속 API30 CJK 장문/가로 카드

초기 0.1.6 개발에서는 기기가 없어 단위/빌드까지만 완료했다. 후속 실행은 시작 RAM 6,201MiB로 기준을 충족해 소유 API30 x86_64 환경을 사용했다. 제품/SDK/로그 보호/R8 규칙은 바꾸지 않고 같은 제품 APK로 다음 결과를 확인했다.

`reading-content`는 작성된 CJK 장문으로 전환했을 때 기존 기본 결과와 다른 새 번역/대상 언어의 도서관·시간 앵커, 멈춤 시 제거·재개 후 결과, 기본 예문 복귀 후 결과 변경을 확인했다. 세 경우 모두 `limit=false`가 관찰됐다. UI에 제공한 전체 원문의 길이는 ja 731/zh 755/ko 710 코드포인트였지만 이는 OCR로 읽힌 한 문단의 길이가 아니다. 전체 문단이 모두 번역됐다는 뜻도 아니다. 영어의 엄격한 분량 제한 발생·제거·재개 검사는 `reading-limits`에 그대로 남겼다.

`reading-rotation`은 실제 번역 뒤 반대 화면 축에서 native 본문 viewport 높이72dp/폭200dp 이상, 가로 패널 폭, 최소48dp 제어/출처 배지의 카드 내부 배치를 확인했다. 멈춤/재개와 원래 축 복귀 후 새 번역/서비스 유지, 회전·언어 설정 복원·로그 검사도 통과했다. 모든 원문이 카드 밖에 남는다고 보증하는 검사는 아니다.

초기 실패 두 가지는 통과에 포함하지 않았다. 회전 검사가 Flutter 페이지 ScrollView를 카드로 측정하던 문제는 native TextView의 부모로 한정해 수정했다. CJK 전체 예문이600자 초과라는 이유로 실제 인식 문단도600자를 넘는다고 가정한 quota 검사는 CJK 장문 읽기와 분리했다. 실제 source OCR 길이를 얻으려던 UI 진단은 값을 확보하지 못했으므로 근거로 사용하지 않았고 최종 도구에서는 제거했다. 최종 관찰값은 작성된 UI 문자 수/경계·제한 여부일 뿐이다. 예상된 API30 QA 이미지 파일을 확보하지 못했으며 보안 보호를 해제하거나 우회하지 않았다.

혼합 Bitmap의 단어 관찰표는 API36과 같았다. 영어 선택에서는 library, 각 CJK 선택에서는 자기 언어 명사와 library가 관찰됐고 나머지 명사는 미관찰이었다. 이는 전체 문장 인식률/문자 체계 지원표/자연스러움 평가가 아니다. Bitmap은 화면 공유를 사용하지 않는다. release 검사는 매번 새 공유 동의, 작성된 입력, 원문 앵커·번역 본문 로그 부재/로그 양성 대조, 설정 복원을 유지했다. [명령](QA.md).

API36의 새 가로 레이아웃/크게 확대한 글꼴/TalkBack/다른 화면 비율/ARM64·OEM/전체 의미·자연스러움/실기기 성능은 남아 있다. 샘플 전용/외부 배포 보류를 유지한다.

## Bitmap fixture 재현

기존 debug 제품 APK를 재사용할 수 있다. 제품/SDK를 바꿨다면 `-SkipBuild`를 생략한다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
Push-Location android
.\gradlew.bat :app:assembleDebugAndroidTest --console=plain
Pop-Location
.\scripts\verify-privacy.ps1 -Variant debug -SkipBuild -DebugSuite multilingual
```

12개 테스트가 번역 방향 하나씩을 담당해 한 방향 실패가 나머지 방향을 건너뛰게 하지 않는다. 모델이 없으면 클래스 준비 단계에서 Wi-Fi 조건으로 ko/ja/zh 모델을 한 번씩 준비한다. 모델 준비가 실패하면 같은 실패를 각 방향에서 반복 다운로드하지 않는다. 새 번역 네트워크 API나 유료 서비스를 사용하지 않는다. 제품의 저장된 언어/주기는 변경하지 않는다.

기본 debug `privacy` 검사는 기존 `PrivacyPipelineTest` 한 개만 명시적으로 선택한다. 다국어 검사는 선택 옵션이며 기본 검사에 모델 다운로드를 추가하지 않는다. 서로 다른 테스트 수를 검사해 12개 중 일부만 실행된 결과를 성공으로 간주하지 않는다.

이 테스트는 뷰 트리/화면 제어를 사용하지 않는다. API31 이상에서는 공개 [UiAutomation.FLAG_DONT_USE_ACCESSIBILITY](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_USE_ACCESSIBILITY)를 사용해 로그 읽기만 수행한다. API30은 공개 기본 경로를 유지하며 별도 실행 검증이 필요하다. 제품의 AccessibilityService 권한을 추가하거나 SDK 로그 보호를 해제하지 않는다.

OCR 입력은 SDK Task 완료 때 recycle한다. 시험의 await 시간이 끝났다는 이유로 SDK가 사용 중인 Bitmap을 조기 해제하지 않는다. 화면 공유/좌표 제외/Flutter 연습 화면/최적화 release에서의 CJK 경로는 이 Bitmap 검사와 별도다.

공식 참고: [ML Kit OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android), [모델 준비와 번역](https://developers.google.com/ml-kit/language/translation/android). 실제 실행 결과와 APK 해시는 [QA 환경](QA_ENVIRONMENT.md), 후속 범위는 [백로그](BACKLOG.md)를 따른다.
