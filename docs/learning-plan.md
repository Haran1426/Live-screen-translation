# 실시간 화면 번역 앱 학습·개발 계획서

## 1. 프로젝트 목표

Android 휴대폰에서 다른 앱을 사용하는 동안 화면 속 글자를 인식하고, 번역 결과를 화면 위에 표시하는 Flutter 앱을 만든다.

최종 사용자 흐름은 다음과 같다.

```text
앱 실행
→ 원본 언어와 번역 언어 선택
→ 화면 번역 시작
→ 화면 캡처 및 오버레이 권한 승인
→ 다른 앱으로 이동
→ 화면 속 문자를 OCR로 인식
→ 인식된 문장을 번역
→ 화면 하단의 플로팅 패널에 번역문 표시
→ 일시정지 또는 종료
```

이 프로젝트의 첫 번째 목표는 모든 글자를 원래 위치에 덮어쓰는 완성형 번역기가 아니다. 먼저 안정적으로 동작하는 하단 번역 패널을 완성한 뒤 위치 기반 번역으로 확장한다.

## 2. 학습 원칙

강의를 처음부터 끝까지 듣고 개발을 시작하지 않는다. 기능 하나를 정하고, 그 기능을 만드는 데 필요한 개념만 학습한 뒤 바로 프로젝트에 적용한다.

각 기능은 다음 순서로 진행한다.

```text
작은 예제 실행
→ 동작 원리 확인
→ 프로젝트에 적용
→ 실패 상황 처리
→ 코드 정리
→ Git 커밋
→ 학습 기록 작성
```

코드를 그대로 복사한 상태는 완료로 보지 않는다. 최소한 다음을 설명할 수 있어야 한다.

- 입력값은 어디에서 들어오는가?
- 상태는 어디에 저장되는가?
- 상태가 바뀌면 어떤 UI가 다시 그려지는가?
- 비동기 작업이 실패하면 어디에서 처리하는가?
- 화면이나 앱을 종료하면 사용하던 자원이 정리되는가?
- Flutter와 Android 네이티브 코드 사이에 어떤 값이 오가는가?

## 3. 첫 번째 배포 범위

### 반드시 구현할 기능

- Android 지원
- 영어 원문을 한국어로 번역
- 번역 시작, 일시정지, 종료
- Android 화면 캡처 권한 요청
- 1초 간격 화면 분석
- 화면의 영어 문장 OCR 인식
- 기기 내 번역 모델을 사용한 번역
- 다른 앱 위의 하단 번역 패널
- 같은 문장을 반복 번역하지 않는 처리
- 권한 거절, 모델 다운로드 실패, OCR 실패 안내
- 캡처 중임을 알리는 지속 알림

### 첫 번째 버전에서 제외할 기능

- iOS 지원
- 회원가입과 로그인
- 서버와 데이터베이스
- 번역 기록 동기화
- 모든 언어 자동 감지
- 원문의 정확한 위치를 덮는 번역
- 초당 수십 프레임 처리
- 디자인 시스템이나 복잡한 애니메이션

제외한 기능은 앱이 안정적으로 동작한 후 추가한다.

## 4. 기술 구성

| 영역 | 담당 기술 | 역할 |
|---|---|---|
| 앱 화면 | Flutter/Dart | 언어 선택, 시작·중지, 설정, 상태 표시 |
| Android 기능 연결 | MethodChannel | Flutter에서 Kotlin 기능 호출 및 결과 수신 |
| 화면 캡처 | Kotlin + MediaProjection | 다른 앱 화면의 프레임 획득 |
| 문자 인식 | ML Kit Text Recognition | 이미지에서 글자와 좌표 추출 |
| 번역 | ML Kit Translation | 기기 내부에서 영어를 한국어로 번역 |
| 화면 위 표시 | Kotlin Overlay | 다른 앱 위에 번역 패널 표시 |
| 장시간 실행 | Foreground Service | 캡처 중임을 알리고 작업 유지 |

### Flutter와 Kotlin의 역할

Flutter는 사용자가 직접 조작하는 UI와 앱 상태를 담당한다. Kotlin은 Android 운영체제에 직접 접근해야 하는 화면 캡처, 서비스, 오버레이, 특별 권한을 담당한다.

```text
Flutter 버튼
→ MethodChannel
→ Kotlin 화면 캡처 서비스
→ OCR 및 번역
→ 오버레이 갱신
→ 처리 상태를 Flutter에 반환
```

## 5. 권장 프로젝트 구조

처음부터 모든 파일을 만들지 말고, 해당 기능을 구현하는 시점에 추가한다.

```text
lib/
├─ main.dart
├─ screens/
│  ├─ home_screen.dart
│  └─ settings_screen.dart
├─ widgets/
│  ├─ language_selector.dart
│  └─ translation_status_card.dart
├─ models/
│  ├─ language_option.dart
│  └─ translation_result.dart
├─ services/
│  └─ native_screen_translation_service.dart
└─ controllers/
   └─ translation_controller.dart
```

```text
android/app/src/main/kotlin/.../
├─ MainActivity.kt
├─ ScreenCaptureService.kt
├─ ScreenCaptureManager.kt
├─ TextRecognitionManager.kt
├─ TranslationManager.kt
└─ OverlayManager.kt
```

초기에는 Flutter 상태 관리를 `setState`로 시작한다. 여러 화면에서 번역 상태를 공유하기 어려워지는 시점에 `ChangeNotifier` 또는 Riverpod 도입을 검토한다. 상태 관리 패키지 도입 자체를 학습 목표로 삼지 않는다.

## 6. 8주 학습·개발 일정

일정은 주당 약 15시간을 기준으로 한다. 시간이 절반이면 각 단계를 2주로 늘리되 순서는 유지한다.

### 1주차 — 홈 화면과 Flutter 상태

#### 구현 결과

```text
실시간 화면 번역

원본 언어  [영어 ▼]
번역 언어  [한국어 ▼]

[화면 번역 시작]

현재 상태: 대기 중
```

#### 학습 내용

- `MaterialApp`, `Scaffold`
- `StatelessWidget`, `StatefulWidget`
- `Column`, `Row`, `Padding`, `SizedBox`
- 버튼과 드롭다운 이벤트
- `setState`와 위젯 재빌드
- 위젯을 작은 파일로 분리하는 기준

#### 실습 과제

- 언어 선택 UI 만들기
- 원본 언어와 번역 언어가 같으면 시작 버튼 비활성화
- 시작 버튼을 누르면 상태를 `준비 중`으로 변경
- 중지 버튼을 누르면 `대기 중`으로 복귀

#### 완료 조건

- 작은 화면에서도 레이아웃이 넘치지 않는다.
- 선택된 언어가 UI와 상태에 동일하게 반영된다.
- `main.dart`가 앱 실행과 테마 설정만 담당한다.

#### 권장 커밋

```text
feat: add translation home screen
feat: add source and target language selectors
feat: add translation status control
```

### 2주차 — 비동기 처리와 가짜 번역

#### 구현 결과

버튼을 누르면 1초 동안 로딩 상태가 표시되고 가짜 번역 결과가 나타난다.

```text
원문: Start a new game
번역: 새 게임 시작
```

#### 학습 내용

- Dart 클래스와 생성자
- `final`, `const`, nullable 타입
- `Future`, `async`, `await`
- `try-catch-finally`
- 로딩, 성공, 실패 상태 모델링
- UI와 처리 로직을 분리하는 이유

#### 실습 과제

- `TranslationResult` 모델 작성
- 1초 뒤 결과를 반환하는 가짜 서비스 작성
- 로딩 중 버튼 중복 클릭 방지
- 일부러 예외를 발생시켜 오류 메시지 표시

#### 완료 조건

- 비동기 작업 중 중복 요청이 발생하지 않는다.
- 성공·실패·대기 상태를 화면에서 구분할 수 있다.
- UI 파일에서 번역 처리 세부 구현이 분리되어 있다.

### 3주차 — 이미지 선택과 OCR

#### 구현 결과

```text
이미지 선택
→ 선택한 스크린샷 미리보기
→ OCR 실행
→ 인식한 원문 표시
```

#### 학습 내용

- 패키지 문서를 읽는 방법
- Android 파일 접근과 권한
- 이미지 경로와 바이트 데이터
- OCR의 블록, 줄, 단어, bounding box
- 플랫폼별 설정 파일의 역할

#### 실습 과제

- 갤러리에서 스크린샷 선택
- 영어가 포함된 이미지에서 텍스트 추출
- 글자가 없으면 별도 안내 표시
- 긴 문장을 스크롤 가능한 영역에 표시

#### 완료 조건

- 실제 휴대폰 스크린샷 5개 중 대부분에서 읽을 수 있는 원문이 나온다.
- OCR 실패와 글자 없음 상태가 구분된다.
- 이미지 자체를 불필요하게 영구 저장하지 않는다.

#### 확인 질문

- OCR은 전체 문자열 외에 어떤 구조로 결과를 반환하는가?
- 글자 좌표는 이후 어떤 기능에 사용할 수 있는가?
- 해상도를 줄이면 속도와 정확도는 어떻게 바뀌는가?

### 4주차 — 실제 번역 연결

#### 구현 결과

```text
이미지 선택
→ 영어 OCR
→ 영어 문장 표시
→ 한국어 번역
→ 번역문 표시
```

#### 학습 내용

- ML Kit 번역 모델 다운로드
- 모델 준비 전·후 상태 관리
- 네트워크가 필요한 시점과 필요하지 않은 시점
- 여러 비동기 작업을 순서대로 실행하는 방법
- 서비스 객체와 자원 해제

#### 실습 과제

- 영어→한국어 번역 모델 다운로드 상태 표시
- Wi-Fi가 없거나 다운로드가 실패한 경우 재시도 제공
- OCR 결과가 이전과 같으면 재번역하지 않기
- 번역 중 앱을 나갔다 돌아오는 상황 확인

#### 완료 조건

- 한 장의 스크린샷이 OCR부터 번역까지 이어진다.
- 모델 다운로드 중 사용자에게 현재 상태가 표시된다.
- 오류가 발생해도 앱이 종료되지 않는다.

#### 첫 번째 마일스톤

`v0.1-image-translation` 태그를 만든다. 이 버전은 실시간은 아니지만 OCR과 번역이라는 핵심 기술을 실제로 검증한 상태다.

### 5주차 — Kotlin과 MethodChannel

#### 구현 결과

```text
Flutter 버튼
→ Kotlin 메서드 실행
→ Kotlin 결과 문자열
→ Flutter 화면에 표시
```

#### 필요한 Kotlin 문법

- `val`, `var`
- 함수와 클래스
- nullable 타입과 안전 호출
- `if`, `when`
- 람다와 콜백의 기본 형태
- Android `Activity`, `Intent`, `Context`

Kotlin 전체 문법이나 Android 앱 UI 제작을 별도 과정으로 공부할 필요는 없다. 화면 캡처 기능을 이해하는 데 필요한 범위부터 학습한다.

#### 실습 과제

- `MethodChannel` 채널 하나 만들기
- `getPlatformMessage` 같은 작은 메서드 호출
- 인자를 Kotlin으로 전달하기
- 성공값과 오류값을 Flutter로 반환하기
- 존재하지 않는 메서드 호출 처리

#### 완료 조건

- 호출 방향과 반환 방향을 직접 설명할 수 있다.
- Kotlin 오류가 Flutter에서 사용자 메시지로 변환된다.
- 채널 이름과 메서드 이름이 한곳에서 관리된다.

### 6주차 — Android 화면 캡처

#### 구현 결과

```text
번역 시작
→ 화면 공유 권한 요청
→ 승인
→ 화면 한 장 캡처
→ OCR 결과 확인
```

#### 학습 내용

- Android `MediaProjection`
- 권한 요청과 결과 처리
- 포그라운드 서비스와 지속 알림
- Android 생명주기
- 화면 방향과 이미지 크기
- 사용자가 캡처 권한을 취소했을 때 처리

#### 실습 과제

- 권한 승인과 거절 흐름 구현
- 캡처 시작 알림 표시
- 화면 한 장을 이미지로 변환
- 캡처된 이미지를 OCR에 전달
- 종료 시 캡처 자원 해제

#### 완료 조건

- 앱 밖의 일반 화면을 한 번 캡처할 수 있다.
- 권한 거절 후 다시 요청할 수 있다.
- 캡처 종료 후 서비스와 알림이 남지 않는다.
- 캡처 방지 화면이 검게 나오는 것을 앱 오류와 구분한다.

### 7주차 — 반복 번역과 오버레이

#### 구현 결과

다른 앱을 사용하는 동안 하단의 반투명 패널에 번역 결과가 표시된다.

#### 기본 처리 규칙

```text
1초마다 최신 화면 요청
→ OCR 처리 중이면 새 프레임 버림
→ 인식 결과 정리
→ 이전 텍스트와 같으면 종료
→ 달라졌으면 번역
→ 오버레이 내용 갱신
```

#### 학습 내용

- 반복 작업과 취소
- 작업 중복 방지
- 문자열 정규화와 비교
- `SYSTEM_ALERT_WINDOW` 특별 권한
- Android WindowManager 기반 오버레이
- 터치 통과 여부와 닫기 버튼
- 메모리·배터리·발열 관찰

#### 실습 과제

- 1초 간격 반복 캡처
- OCR이 끝나기 전에 다음 요청이 쌓이지 않도록 제한
- 공백만 다른 결과를 같은 문장으로 처리
- 화면 하단에 번역 패널 표시
- 플로팅 패널에서 일시정지와 종료 제공

#### 완료 조건

- 10분 이상 실행해도 앱이 종료되지 않는다.
- 이전과 같은 문장을 계속 번역하지 않는다.
- 중지 후 캡처, OCR, 알림, 오버레이가 모두 종료된다.
- 사용자가 언제 캡처 중인지 명확하게 알 수 있다.

#### 두 번째 마일스톤

`v0.2-live-overlay` 태그를 만든다. 실제 작동 영상을 촬영한다.

### 8주차 — 안정화, 테스트, 포트폴리오

#### 테스트 시나리오

- 최초 실행 후 권한 승인
- 화면 캡처 권한 거절
- 오버레이 권한 거절
- 번역 모델 다운로드 실패
- 네트워크 연결 해제
- 글자가 없는 화면
- 같은 화면을 오래 유지
- 화면 회전
- 앱을 백그라운드와 포그라운드로 반복 이동
- 알림에서 서비스 종료
- 앱 강제 종료 후 잔여 오버레이 확인
- 글자가 많은 화면과 작은 글자 화면

#### 포트폴리오 자료

- 10~30초 작동 영상 또는 GIF
- 핵심 화면 스크린샷

## 9. Git 사용 규칙

작동하는 작은 단위마다 커밋한다.

```text
feat: add language selection
feat: recognize text from selected image
feat: add on-device translation
feat: request screen capture permission
feat: show translated text in overlay
fix: prevent duplicate OCR processing
fix: stop overlay when capture ends
docs: document screen capture architecture
refactor: separate translation service from UI
```

기능 하나를 개발할 때 권장 흐름:

```powershell
git pull
git checkout -b feature/image-ocr

# 작업과 테스트

git add .
git commit -m "feat: recognize text from selected image"
git checkout main
git merge feature/image-ocr
git push
```

초기에는 혼자 개발하더라도 기능 브랜치를 사용하면 변경 단위와 병합 과정을 연습할 수 있다. 단, Git이 아직 부담스럽다면 첫 1~2주는 `main`에서 작은 커밋을 남겨도 된다.

절대로 저장소에 올리지 않을 항목:

- API 키와 비밀번호
- 서명용 keystore 파일과 비밀번호
- 개인 정보가 포함된 실제 캡처 이미지
- 회사 또는 다른 사람의 비공개 코드
- 로컬 빌드 결과와 캐시

## 10. 테스트 기준

### 기능 테스트

- 버튼을 빠르게 여러 번 눌러도 중복 서비스가 시작되지 않는다.
- 권한을 거절해도 앱이 종료되지 않는다.
- OCR 결과가 없을 때 이전 번역문이 잘못 남지 않는다.
- 번역 중지 후 추가 OCR이 실행되지 않는다.
- 화면 회전 후 상태가 비정상적으로 중복되지 않는다.

### 성능 관찰

- 한 번의 OCR 처리 시간
- 한 번의 번역 처리 시간
- 10분 실행 시 발열 정도
- 같은 문장의 중복 번역 횟수
- 캡처 이미지 해상도에 따른 정확도 차이

처음부터 완벽한 성능 측정 도구를 만들 필요는 없다. 처리 시작·종료 시간을 로그로 남겨 비교하는 것부터 시작한다.

## 11. 개인정보와 배포 준비

화면 캡처 앱은 메시지, 계정 정보, 결제 정보처럼 민감한 내용을 볼 수 있다. 따라서 기능만큼 사용자 신뢰가 중요하다.

첫 버전의 원칙:

- 캡처 이미지를 기기에 저장하지 않는다.
- 가능하면 OCR과 번역을 기기 안에서 처리한다.
- 캡처 중임을 지속 알림과 오버레이로 표시한다.
- 사용자가 언제든 즉시 중지할 수 있게 한다.
- 수집하거나 전송하는 데이터가 있다면 명확하게 설명한다.
- 로그에 화면 원문이나 번역문 전체를 남기지 않는다.

Google Play 배포 전에는 당시 최신 정책을 다시 확인한다. 특히 화면 캡처, 포그라운드 서비스, 다른 앱 위 표시 권한, 개인정보처리방침, 데이터 보안 항목을 검토한다.

## 12. 포트폴리오 설명 구조

### 문제

외국어 게임이나 앱을 사용할 때 화면을 오가며 번역기에 문장을 입력해야 하는 불편이 있다.

### 해결

Android 화면을 사용자의 동의 아래 캡처하고, 기기 내 OCR과 번역을 거쳐 다른 앱 위에 번역 결과를 표시한다.

### 기술적 선택

- UI는 Flutter로 구성해 화면 개발과 상태 관리를 담당했다.
- Android 전용 화면 캡처와 오버레이는 Kotlin으로 구현했다.
- 화면 데이터를 외부 서버에 보내지 않도록 기기 내 OCR과 번역을 우선 사용했다.
- 과도한 처리 방지를 위해 이전 텍스트와 비교하고 처리 중 새 프레임을 버렸다.

### 해결할 문제 사례

- Flutter와 Kotlin 간 비동기 통신
- 캡처 권한과 서비스 생명주기 관리
- 중복 OCR 및 번역 요청 제한
- 화면 좌표와 오버레이 좌표 변환
- 권한 거절과 서비스 강제 종료 복구

포트폴리오에서는 사용한 기술 목록보다 왜 그 기술을 선택했고 어떤 문제를 해결했는지를 중심으로 설명한다.

## 13. 이후 확장 순서

첫 배포가 안정화된 뒤 다음 순서로 확장한다.

1. 번역 패널 위치와 투명도 설정

8. iOS 가능 범위 별도 조사 및 프로토타입

위치 기반 번역에서는 OCR의 `boundingBox`를 화면 좌표로 변환해야 한다. 캡처 이미지 크기, 실제 화면 크기, 회전, 상태 표시줄 영역이 다를 수 있으므로 단순히 같은 좌표를 사용하면 어긋날 수 있다.
