# 개발 기록

## 2026-11-19 · 최초 구현 (한국 시간)

사용자 요청: 휴대폰 실시간 화면 번역 앱을 기획부터 초기 개발까지 높은 품질로 자율 개발하고 정기적으로 이어가기.

시작 상태는 Flutter 3.44.6/Dart 3.12.2 기본 카운터 템플릿이며 Git 저장소가 아니다. 사용자 변경 복원/초기화나 커밋은 하지 않았다. API 36 Medium Phone 에뮬레이터가 연결되어 있었다.

### 구현

- 제품 기획, Flutter/Kotlin 역할 분리, 이어가기/QA/백로그 문서 작성.
- 한국어 홈/언어 선택/권한 및 모델 준비/안내/설정/연습 화면.
- Android 전체 화면 MediaProjection + FGS + 종료 가능한 알림 + 표시 권한 흐름.
- en/ko/ja/zh OCR 엔진, ML Kit 온디바이스 번역 모델 준비/검사, Wi-Fi 조건.
- 보안 오버레이 카드/이동 버튼/접기/멈춤/종료. 공식 Google Translate 배지 표시.
- 이미지 백그라운드 복사, 단일 처리, 동일 원문 비교/세션 캐시, 오래된 응답 무효화, 화면 회전 resize, 잠금/공유 종료 정리.
- 자체 홈/설정/번역 결과를 다시 번역하지 않도록 앱 가시성/연습 화면 구분. 상태표시줄과 오버레이 영역 OCR 제외.
- 모델 상태 조회 실패 후 이미 저장한 언어 설정이 UI에서 되돌아가던 비동기 상태 오류 수정.
- 앱 아이콘 및 Android 12+ 백업/기기 이전 제외 규칙 추가.

### 확인한 결과

- `flutter analyze`: 오류 없음.
- `flutter test`: 10개 통과. 권한/모델 게이트, 동의 취소와 재시도, 다운로드 실패 복구, 활성 중 설정 잠금, 일시정지/종료 시 결과 초기화, 권한 해제 재조회, 저장 상태 일치, 안내/설정 탐색, 360dp 및 320dp/1.4배 글꼴 회귀 포함.
- `:app:testDebugUnitTest`: 5개 통과. 언어/주기 경계 검사와 종료/실패 시 민감한 텍스트 제거, 리스너 해제 검증.
- debug APK 빌드/설치 성공.
- ABI별 release APK 빌드 성공. 최초 R8 최적화 빌드의 모델 초기화 예외는 제거된 ComponentRegistrar 기본 생성자가 원인임을 usage/mapping으로 확인하고 좁은 보존 규칙으로 수정했다. 수정 후 x86_64 release 설치/모델 조회/실제 OCR·번역을 확인했다. arm64 테스트 APK는 약 46MB. 모든 빌드는 아직 debug 키로 서명한다.
- `:app:lintDebug`: 통과(오류 0, 비차단 경고 잔존). Flutter가 매번 생성하는 local.properties의 PropertyEscape 진단만 파일 단위로 제외했다. 내부 inset 리소스 조회는 공개 WindowInsets API로 교체했다. 서비스 플랫폼 테마에서 필요한 TextView에만 AppCompat 진단을 제한적으로 억제했다. KTX 사용 제안/리소스 밀도 등 경고는 기능 오류와 구분한다.

### 에뮬레이터에서 직접 확인

- 표시 권한/모델 상태가 시작 버튼에 반영됨. 첫 한국어 모델 다운로드 완료.
- 매 세션 Android 공유 동의, 선택적 알림 권한 요청과 알림 생성.
- 영어 연습 화면에서 실제 한국어 번역이 오버레이에 표시됨(예: “Take the scenic route” → “경치 좋은 경로를 가져 가라”). 이 문구는 실행 결과이며 별도 번역 품질 보정이 필요하다.
- 다른 앱(홈)으로 이동해도 오버레이 유지.
- 오버레이에서 일시정지하면 본문이 지워지고 멈춤 안내 표시.
- 화면 잠금 이후 서비스가 없어짐을 dumpsys로 확인. 화면을 깨워도 자동 복구하지 않음.
- R8 release에서도 실제 번역/회전 이후 캡처 세션 유지와 결과 표시를 확인했다. 가로 화면 카드의 읽기 영역을 확보하고 좌/우 시스템바 제외도 추가했다. 연속 회전과 모든 구형 OS는 추가 검증이 필요하다.
- 보안 오버레이는 adb 스크린샷에서는 검은 영역으로 표시되고 실제 Android Studio Running Devices에서는 정상 표시됨.

### 주의/후속

ML Kit native Logcat에서 번역 내용이 출력되는 것을 **debug/release 양쪽에서 확인**했다. 앱 코드에는 원문 로그가 없지만 SDK 로그는 별도 해결이 필요하다. R8 release의 연습 화면 테스트 프로세스에서도 해당 패턴 로그 15줄, 치명적 예외 0건을 확인했다. 테스트는 직접 작성한 샘플에 한정하며 외부 배포하지 않는다. 지원되는 SDK 로그 제어 또는 대안 엔진 검토가 다음 자동 개발의 최우선 항목이다.

일본어/중국어/한국어 원문 실제 품질, API 26~34, OEM 기기, 장시간 발열/전력, 연속 회전/권한 취소/시스템 공유 종료는 미검증 항목이다. 전체 TODO 목록은 BACKLOG/QA를 따른다.

## 2026-11-19 · 03:40 정기 개발 · 0.1.1

### 변경

- SDK를 교체하거나 내부 API를 조작하지 않고 공개 Android NDK 로거 콜백으로 앱 프로세스의 텍스트 로그를 차단했다. 정보 로그는 버리고 경고/오류는 고정 문구와 심각도만 남긴다. 원래 태그/본문/파일명/예외 문자열을 복사하지 않는다.
- 모든 Translator 생성 전에 보호를 설치한다. JNI 라이브러리를 읽을 수 없으면 번역기 생성을 거부한다. 추가된 보존 규칙은 JNI 경계 클래스에만 적용했다.
- 공개 API가 있는 Android 11(API 30)로 최소 버전을 조정했다. 이전 Android 8~10 지원을 유지하려고 숨은 API를 호출하는 방식은 선택하지 않았다. 호환성 변경은 README/기획/설정 화면에 표시했다.
- debug에는 메모리 Bitmap → OCR → 실제 한국어 번역 → 로그 검사 통합 테스트를 추가했다. release에는 프레임워크/Java API만 쓰는 별도 Instrumentation으로 실제 앱 UI/화면 공유 동의/연습 화면/오버레이/프로세스 로그 검사를 추가했다. 앱의 SDK 및 Kotlin 심볼을 테스트가 직접 참조하지 않으므로 R8 규칙을 테스트 때문에 느슨하게 만들 필요가 없다.
- `scripts/verify-privacy.ps1`로 두 경로를 재현한다. 실제 폰을 대상으로 실행하지 않으며, 설치 직후 ADB 재연결은 15초 안에서 한 번만 복구한다. 실제 assertion 실패는 자동으로 재시도하지 않는다. 로그 버퍼를 삭제하지 않는다.
- 모델 준비가 2분 넘게 응답하지 않을 때 UI 잠금을 풀고 회복 안내를 표시했다. SDK 다운로드 취소를 의미하지 않으며, 늦은 완료가 UI를 임의로 성공으로 바꾸지 않는다. 이후 새로고침으로 실제 상태를 확인한다.

## 2026-11-19 · 정기 개발 · API 30 지원 하한 검증

### 결과

- 별도 Google APIs Android 11(API 30) revision 16 x86_64 에뮬레이터를 준비했다. 기존 API36 Medium Phone은 종료하거나 재설정하지 않았다.
- 동일한 0.1.1 APK에서 debug Bitmap OCR/한국어 번역/원문·번역문 로그 차단 검사 1개 및 실제 최적화 release 화면 공유/오버레이/로그 검사 1개가 통과했다. release의 primaryCpuAbi=x86_64, versionName=0.1.1, minSdk=30, debuggable=false를 확인했다. 매번 실제 Android 동의 UI를 거쳤고 서비스 종료도 확인했다.
- C: 여유 공간이 약 3.2GiB라 큰 SDK/AVD 파일을 D:의 이 프로젝트 전용 QA 폴더에 보관했다. 설치 도구는 공식 checksum을 확인한 Command-line Tools 17.0과 기존 JBR 21이다. 최신 CLI 런타임 초기화가 되지 않아 사용하지 않았고 Windows 보안 정책은 변경하지 않았다. [환경 위치와 재현](QA_ENVIRONMENT.md).

### 도구 개선

- `scripts/verify-privacy.ps1 -SkipBuild`를 추가했다. 소스/테스트보다 오래된 APK와 장치 ABI의 로그 보호 라이브러리가 없는 APK를 거부하고, 검사한 APK SHA-256 및 API level을 출력한다. 앱·SDK·NDK 변경 때는 기본 빌드를 사용한다.
- split release의 ABI-prefixed versionCode 때문에 debug fixture 재설치가 실패하는 경우를 수정했다. debuggable APK에만 ADB의 공개 `-d` 옵션을 사용하며 앱 삭제나 모델 캐시 초기화는 하지 않는다. release는 선택 ABI split APK를 우선하며 기본 빌드도 split APK를 만든다.
- `scripts/api30-qa.ps1`로 소유 AVD만 시작/종료한다. 포트 소유권, 여유 RAM, 부팅 제한 시간, 비교 화면 크기를 확인한다. 이미 실행된 경로·종료 경로·실제 재시작/부팅 완료 경로를 확인했고 PowerShell 구문 오류가 없었다.
- 변경은 QA 스크립트/문서에 한정했다. 앱 소스와 바이너리는 변경하지 않았으므로 이미 통과한 Flutter/Android 단위/lint/빌드를 불필요하게 반복하지 않았다. 수정한 QA 스크립트 전체의 debug/release 경로를 API 30에서 실행해 통과했다.

처음 수동 실행에서 split 빌드 후 사라진 universal APK 경로를 사용해 설치가 실패했고, 이어진 release fixture는 debug APK임을 startup assertion으로 거부했다. 올바른 split APK를 설치한 검사와 최종 스크립트의 양쪽 경로가 통과했다. 앱 오류나 assertion 실패를 숨기기 위해 재시도한 결과가 아니다.

### 다음 작업

ARM64 실기기는 연결되어 있지 않아 미검증으로 남겼다. API30 이미지의 ARM native bridge를 실기기 검사로 간주하지 않는다. 샘플 전용/외부 배포 보류는 유지한다. 실제 장치가 없으면 같은 상태를 반복 확인하기보다 프레임 Task 대기 제한, 생명주기/권한 취소 또는 다국어 fixture 등 다음 독립 작업으로 진행한다.

## 2026-11-19 · 07:52 정기 개발 · 0.1.2

### 변경

- 프레임 픽셀 복사부터 OCR·모든 문단 번역까지 전체 작업에 30초 기한을 적용했다. 완료되지 않으면 서비스/화면 공유/오버레이를 종료하고 새 시작을 안내한다. 자동 세션 재시작이나 동의 토큰 재사용은 없다.

영어→중국어는 최초 경치/경로 앵커를 찾지 못했다. 진단만 추가한 실행에서 native 본문의 존재/한자/제목의 모험 의미가 각각 true임을 확인했다. 작성된 제목의 모험 앵커도 허용하고 영어 원문 제목 존재를 확인하도록 바꾼 뒤 통과했다. 결과를 출력하거나 번역을 바꾼 해결이 아니다. 진단 소스를 배치 실행 중 추가해 최신성 보호가 거부한 나머지 5개는 미실행으로 분류했고, rebuild 후 실패 방향과 미실행 방향만 이어갔다. 이미 통과한 6개 방향을 다시 돌리지 않았다.

제품 release SHA-256은 계속 `D41B4D5C37FDB0CB8567D8C7B00A133C450D8BF465EA1A9826FF30A4F771AF02`다. 마지막 6개에 사용한 최종 test APK는 `2B9C9081DEC8D3646B7851BDE5A2FC5EBD95CCBB27FCDD6275161F1B3937A681`이다. 먼저 통과한 6개는 진단/영어 앵커 보강 전 fixture의 결과임을 구분했다.

### 남은 작업과 정리

기본 단어/시간 확인은 문장 전체 의미·부정/시간 관계·자연스러움, 긴 문단·혼합 언어·모든 문단의 인식률을 평가하지 않는다. API30 CJK/12방향, API33·34, ARM64/OEM/성능도 미검증이다. 다음 독립 P0는 직접 작성한 긴 문단/혼합 언어 케이스로 누락·잘림·레이아웃과 필요한 안내를 확인하는 것이다. 샘플 전용/외부 배포 보류를 유지한다.

최종 검사 후 서비스/활성 공유가 없음을 확인하고 기존 release 홈으로 복귀했다. 장치 목록에는 기존 emulator-5554만 남았으며 설정/모델은 보존했다. 빌드 후 유휴 Gradle daemon은 정상 종료했다. 커밋/푸시/외부 배포는 하지 않았다.

한 시간 간격 자동화는 ACTIVE로 유지하고 12방향 완료 기록과 다음 긴 문단/혼합 언어 QA 단계로 갱신했다.

## 2026-11-19 · 정기 개발 · 0.1.5 일부 번역 안내와 장문/혼합 연습

연결 장치는 기존 API36 emulator-5554뿐이었다. ARM64 실기기를 반복 조회하거나 새 SDK를 설치하지 않고 다음 독립 P0인 장문/혼합 QA와 분량 제한 고지를 진행했다.

### 변경

- 기존 서비스는 OCR 문단을 12개/각 600 UTF-16 단위로 조용히 잘랐다. `FrameTextSelection`으로 범위를 분리하고 문단 제외/축약 시 카드·홈의 상태 메시지에 일부 번역과 스크롤 안내를 표시한다. 캡처 원문을 안내에 넣지 않는다.
- 문단당 600 Unicode 코드포인트로 선택해 surrogate pair를 쪼개지 않는다. 문장/복합 grapheme 경계나 모든 OCR 누락을 탐지하는 기능은 아니다. 기존의 짧은 조각/가림 제외 정책은 유지한다.
- 같은 번역 앞부분에 제한 메타데이터만 달라지면 이전 결과를 재사용하면서 안내를 갱신한다. 멈춤/회전/오류/종료 시 이전 선택을 비운다. 프레임 30초 기한·캐시 용량·늦은 응답 차단은 유지한다.
- PracticeScreen 메뉴에서 기본 예문/긴 문단·혼합 언어를 바꾼다. 네 원문 언어별 600자 초과의 작성된 예문과 혼합 행, 복사, 같은 bridge 가시성을 제공한다. 전환 자체가 캡처를 시작하지 않는다. 기본 예문 배치는 유지했다.
- 버전/설정 표시를 0.1.5+6으로 맞췄다. SDK/NDK/의존성/로그 보호/ProGuard/동의·자동 재시작 정책은 바꾸지 않았다.

### 검증

- Flutter 분석 진단 없음, 테스트 25개 통과. 추가 4개는 각 언어에서 320dp·1.4배 글꼴의 장문 전환/스크롤/원문 복사/기본 복귀/bridge 가시성 유지·해제를 검사한다. 최초 메뉴 Text 탭은 CheckedPopupMenuItem 내부 IgnorePointer에 대한 경고가 있어 항목을 탭하고 기본 예문 제목까지 확인하도록 보강했다. 테스트의 괄호 스타일 진단도 수정했다.
- Android 단위 20개, 실패/오류 0. 새 7개는 12/600 정확한 경계·초과·공백/조각 필터·순서·혼합 문자 보존·surrogate pair·동일 앞부분의 다른 제한 메타데이터와 안내의 원문 미포함을 검사한다. 기존 FrameWorkGuard/SessionStore 회귀도 포함한다.
- debug 및 3개 ABI split release 빌드 성공. debug 일반 Bitmap OCR/기기 내 번역/로그 1개는 설치 직후의 시작 상태만 남은 실행을 통과로 계산하지 않고 재설치 없는 직접 Runner에서 `OK (1 test)`를 확인했다. 이 debug는 같은 제품 코드의 fixture versionCode 4005다.
- API36 실제 최적화 release `reading-limits` 1개 통과. 새 Android 동의/기본 번역 → 장문·혼합 행 → 실제 native 일부 번역 안내/한국어 결과 → 멈춤 시 제거/재개 시 복원 → 기본 예문 복귀 후 안내 해제, 로그 양성 대조/원문 앵커·번역 본문 부재/원래 언어 설정 복원을 확인했다. 12문단 초과와 같은 앞부분의 메타데이터 변경은 단위 범위이며 실제 SDK를 조작한 시험이 아니다.
- 최종 debug(versionCode 4006)에서 `MixedReadingTest` 4개가 한 번의 실행으로 통과했다. 작성된 네 언어 행을 같은 Bitmap에 넣었을 때 영어 선택은 library만, 각 CJK 선택은 자기 언어 명사와 library가 관찰됐다. A17 식별자와 로그 양성 대조도 통과했다. 다른 세 언어 명사 중 미관찰이 있음을 boolean으로만 기록했고 결과/예외 본문을 출력하지 않았다. [관찰표](MULTILINGUAL_QA.md).
- Android lint 오류 0/경고 16. 기존 Kotlin/Gradle 사용 중단 경고 등은 남아 있다.

### 빌드 환경과 한계

혼합 fixture를 위한 후속 debug 빌드에서 기존 8GiB Gradle daemon이 예기치 않게 종료됐다. 원인을 메모리로 확정하지 않았다. 프로젝트/전역 설정을 바꾸지 않고 해당 실행에만 `-Xmx2048m`, metaspace 768MiB, 작업자 2개와 single-use Gradle을 지정해 debug/test APK/lint를 완료했다. 최종 Gradle debug APK를 Flutter 출력 경로에도 맞췄다. 동일 제품 코드의 debug SDK 1개를 중복 실행하지 않고 새 혼합 4개만 최종 debug에서 검사했다.

최종 debug SHA-256은 `5A52D8D49AD470A838021595A7D807969DF47C6BF24BC99D3098CA509A60C2C6`, release x86_64는 `F50B16D9DFEC836CE844E36A790373C4D440F4282F18B8AEC5387778B5069D46`다. release 메타데이터는 0.1.5/4006이며 SDK 보호/동의를 유지한 개발용 서명이다. 이 실행의 실제 장문 release는 영어→한국어만 확인했다. CJK 장문/가로 카드/의미·자연스러움/실기기 성능은 미검증이다.

API30 시작 전 여유 RAM은 약 1,018MiB여서 기존 시작 기준을 낮추거나 VM/다른 앱을 종료하지 않고 추가 실행을 하지 않았다. API30/ARM64의 새 기능 미검증과 샘플 전용/외부 배포 보류를 유지한다. 기존 0.1.4의 12방향 전체 검사는 변경 없는 번역 SDK에 대해 반복하지 않았다.

최종 release와 release test APK를 emulator-5554에 복원하고 홈을 열었다. 서비스/활성 공유가 없고 기존 장치만 남았음을 확인했다. single-use 빌드 프로세스는 종료됐고 기존 설정/모델을 유지했다. 한 시간 간격 자동화는 ACTIVE로 갱신했으며 다음 독립 P0는 CJK 장문/가로 카드 검증과 필요한 읽기 개선이다. 커밋/푸시/외부 배포는 하지 않았다.

## 2026-11-19 · 정기 개발 · 0.1.6 가로 카드 읽기 구조

시작 시 ADB 장치 목록이 비어 있었다. 여유 RAM은 약 2,777MiB로 소유 QA VM의 3,000MiB 시작 기준에 못 미쳤다. 기존 VM/다른 앱을 시작·종료·재설정하거나 기준을 낮추지 않고 독립적으로 가능한 레이아웃 보강과 회귀 도구/빌드를 완결했다. 실제 CJK 장문과 회전 실행은 미완료로 남긴다.

### 변경

- 기존 가로 카드도 높이를 화면의 절반으로 제한하고 헤더/상태/하단 제어를 모두 쌓아 본문 영역이 줄어드는 구조였다. 순수 dp 정책 `OverlayCardLayout`을 추가했다. 가로는 한쪽의 300~420dp 폭, 세로 여백 내 300dp 목표 높이를 사용한다. 일반 세로는 기존 300dp/절반 상한을 유지하고 글꼴 배율에 따라 목표 높이를 늘린다.
- 가로에서는 멈춤/종료 View를 헤더로 옮기고 비어 있는 하단 행을 숨긴다. 제목은 짧게 하며 세로 복귀 시 기존 제어 행과 제목을 복원한다. 상태 안내/본문 ScrollView/공식 출처/48dp 이상 제어·FLAG_SECURE/실제 위치 기반 제외는 유지했다. 실제 View가 모든 글꼴에서 맞는다는 검증은 아니다.
- release fixture의 `reading-limits`를 네 원문 언어의 장문 제목/원문/번역 앵커에 맞췄다. 영어의 기존 혼합 행 검사를 유지했다. 새 `reading-rotation`은 화면 축 전환 뒤 본문 viewport/제어/배지 경계·제어 동작과 원래 축 복귀를 검사하도록 준비했다. 회전/자동 회전 설정은 키 부재까지 복원·확인하며 실패하면 성공으로 처리하지 않는다. 테스트 APK만의 공개 프레임워크 API를 사용한다.
- pubspec/설정 표시를 0.1.6+7로 맞췄다. SDK/NDK/의존성/로그 보호/ProGuard/동의 토큰/서비스 재시작 정책은 바꾸지 않았다.

### 검증 범위

- Flutter 분석 진단 없음. Dart UI 변경은 표시 버전뿐이라 기존 Flutter 25개를 다시 실행하지 않았다.
- 최종 native 단위 25개 통과, 실패/오류 0. 추가 레이아웃 회귀는 세로 기본 크기, 가로 읽기 높이·남는 원문 영역, 작은 가로 화면, 글꼴 확대와 화면 여백, 세로 절반 상한의 5가지 실제 읽기 조건이다. 기존 20개도 포함한다. 정책의 수학적 크기와 Android View의 실측은 구분한다.
